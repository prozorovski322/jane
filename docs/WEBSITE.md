# Сайт

Jane — прежде всего сайт. Это тот же код на Expo, собранный для браузера (react-native-web,
`web.output: "single"` — одностраничное приложение). Приложение для iOS и Android собирается из
него же.

## Сборка и проверка

```bash
npm run content:build   # если менялся контент
npm run web:build       # сайт в dist/
npm run web:serve       # dist/ на http://localhost:8090
```

`web:build` сохраняет экспорт Expo как `app.html`, а в `index.html` устанавливает публичную
главную из `scripts/web/landing.html`. Её CSS, JavaScript и локальные шрифты лежат в `public/landing/`.
`web:serve` отдаёт главную на `/`, а `app.html` — на неизвестные пути, с заголовками изоляции.
Перед публикацией откройте сайт через него, а не через dev-сервер.

## Что нужно от хостинга

1. **Два заголовка на всех ответах.** Без них не откроется база данных (expo-sqlite в браузере
   работает через WebAssembly и `SharedArrayBuffer`, а он есть только на изолированных страницах):

   ```
   Cross-Origin-Embedder-Policy: require-corp
   Cross-Origin-Opener-Policy: same-origin
   ```

   Именно `require-corp`, а не `credentialless`: второй вариант не поддерживает Safari. Сайт не
   загружает ничего с чужих доменов, поэтому `require-corp` ему не мешает. Если когда-нибудь
   появятся чужие ресурсы (шрифты, картинки, счётчики), их сервер должен отдавать
   `Cross-Origin-Resource-Policy: cross-origin`, иначе браузер их не загрузит.

2. **Неизвестный путь → `app.html`** (код ответа 200), корень `/` отдаёт `index.html`.
   `/course` открывает действующий курс; `/auth`, `/profile` и ссылки на уроки работают напрямую.

Существующий Supabase callback на `/` сохранён: `public/landing/callback.js` переносит query/fragment
в `/auth`, где штатный клиент завершает вход и проверку PKCE. Внешние redirect URL не принимаются.
Пробный урок на главной хранит только свои три ответа в отдельном ключе localStorage и не
подменяет прогресс курса. Установленная PWA запускается с `/course`.

Для **Netlify** и **Cloudflare Pages** всё уже настроено: файлы `public/_headers` и
`public/_redirects` попадают в `dist/` при сборке. Публикуется папка `dist/`.

Для других хостингов (Vercel, Firebase, свой nginx) нужно прописать те же два заголовка и
переадресацию в их конфигурации.

**EAS Hosting** задаёт заголовки через `app.json` (плагин `expo-router`, ключ `headers`), но только в
режимах `static` и `server`, не в `single`. Чтобы перейти на EAS Hosting, нужно сначала перевести
сайт на статическую генерацию страниц — это отдельная задача.

## Чем сайт отличается от приложения

- **Данные** хранятся в браузере (хранилище сайта). Очистка данных сайта стирает прогресс,
  поэтому в настройках предлагается сохранять копию в файл. В приватном режиме браузера данные
  исчезнут после закрытия окна.
- **Распознавание речи** делает браузер (Web Speech API): Chrome отправляет звук в Google, Safari —
  в Apple, Edge — в Microsoft. Поэтому оно включается только в настройках или на последнем шаге
  знакомства, по умолчанию выключено. Firefox распознавания не умеет — там остаётся самопроверка.
- **Озвучка** — голоса браузера и системы (`speechSynthesis`). Набор голосов зависит от браузера.
- **Нет напоминаний и вибрации**: эти пункты на сайте скрыты.
- **Проверка письма нейросетью** недоступна: ключ API негде безопасно хранить в браузере.

## Как сайт загружается

- **Первый экран приложения.** В `public/index.html` внутри `#root` лежит статичная страница загрузки: описание курса,
  уровни, «Загружаем курс…». Её видно, пока скачивается скрипт, и её же читают поисковики.
  Пока открывается база данных, приложение показывает «Загружаем курс…». Шрифты сайт не ждёт:
  текст сначала идёт системным шрифтом. Шрифты на сайте — WOFF2 только с нужными символами
  (около 110 КБ вместо 620 КБ TTF, ssets/fonts/web/, делает
  ode scripts/web-fonts.mjs, нужен
  `pip install fonttools brotli`); приложение для телефона использует полные TTF.
- **Юниты по требованию.** Курс не встроен в основной скрипт: `npm run content:build` кладёт
  каждый юнит отдельным файлом в `public/content/units/` (в имени — хэш содержимого), а сайт
  скачивает юнит, когда он нужен (урок, тест, повторение, практика). Основной скрипт — около
  5,7 МБ (около 1,1 МБ в сжатом виде). Приложение для телефона содержит все юниты внутри.
- **Работа без интернета.** `npm run web:build` после сборки создаёт `dist/sw.js` (шаблон —
  `scripts/web/sw-template.js`). При первом посещении он сохраняет сам сайт (около 7 МБ без
  сжатия), юниты — по мере открытия, в отдельном кэше, который переживает обновления сайта. В
  настройках есть «Сохранить весь курс» (около 4 МБ). Для `sw.js` в `public/_headers` отключено
  кэширование, иначе браузер не увидит обновление.
- **Обновление сайта.** Если сайт обновили, пока вкладка была открыта, старых файлов юнитов на
  хостинге уже нет. Вкладка один раз перезагружается сама и получает новую версию
  (`src/core/content/fetch-web.ts`).
- **Распознавание речи в длинных ответах.** В заданиях с таймером (Part 2) распознавание не
  останавливается на паузах: если браузер обрывает сессию, она перезапускается, текст копится до
  «Закончить ответ» или конца времени.
- **Широкий экран.** От 900 пикселей вкладки становятся боковым меню (220 px, с названием и
  пунктом «Настройки»), экраны, уроки и знакомство стоят колонкой по центру.
- **Клавиатура в уроке.** Enter проверяет ответ и переходит дальше, в том числе после щелчка по
  варианту (фокус остаётся на нём). Цифры 1–9 выбирают вариант в заданиях со списком. В поле для
  эссе Enter — новая строка.

## Поисковики, ссылки, установка

- У каждого адреса свой заголовок (`src/lib/pageTitle.ts`).
- В `index.html` есть описание, `og:title`, `og:description` и `og:image` (`public/og-image.png`,
  1200×630) — ссылка в Telegram и ВК показывается с картинкой. Адреса в них абсолютные
  (`https://jane-english.netlify.app/`): при переезде на свой домен их нужно поменять, как и в
  `robots.txt` и `sitemap.xml`.
- `manifest.webmanifest` и иконки (`icon-192.png`, `icon-512.png`, `apple-touch-icon.png`):
  сайт можно «установить» на телефон. Картинки рисует `node scripts/web-images.mjs` (через
  Microsoft Edge в фоновом режиме), PNG лежат в git.

## Защита

`public/_headers` задаёт `Content-Security-Policy`: всё грузится только с самого сайта, встроенных
скриптов и `eval` нет (регистрация service worker — отдельный файл `public/register-sw.js`).
Исключения: `'wasm-unsafe-eval'` для SQLite и `'unsafe-inline'` для стилей react-native-web.
`npm run web:serve` читает тот же `_headers`, так что локальная проверка идёт с теми же
заголовками, что на Netlify.

## Что стоит сделать дальше

- **Словарь и грамматика** (около 1,1 МБ без сжатия) тоже можно загружать по требованию, но их
  читают многие экраны сразу, так что выигрыш меньше, а переделка больше.

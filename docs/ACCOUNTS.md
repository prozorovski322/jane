# Аккаунты

Вход обязателен, когда аккаунты включены: без входа открываются только экран входа и политика
конфиденциальности. Аккаунт хранит прогресс (синхронизация между устройствами), имя для рейтинга
недели и друзей. Сервер — [Supabase](https://supabase.com): готовые вход и база данных.

Пока переменные окружения не заданы, аккаунты выключены и сайт работает как раньше: всё хранится
только в браузере, вход не спрашивается.

Для `jane-english.netlify.app` выбран проект Supabase `rfxzrleoebkipamwicrb`:
`https://rfxzrleoebkipamwicrb.supabase.co`, регион `eu-west-1` (Ирландия). Локальные параметры
подключения находятся в `.env.local` и не попадают в git.

## Как устроено

| Где                                    | Что                                                                     |
| -------------------------------------- | ----------------------------------------------------------------------- |
| `supabase/migrations/…_accounts.sql`   | таблицы, правила доступа (RLS), функции рейтинга, друзей, удаления      |
| `src/core/account/`                    | настройки (`config.ts`) и клиент Supabase (`client.ts`)                 |
| `src/core/storage/merge.ts`            | объединение прогресса двух устройств без потерь                         |
| `src/features/account/service.ts`      | вход, регистрация, пароль, профиль, друзья, рейтинг, синхронизация      |
| `src/features/account/store.ts`        | состояние входа; синхронизация при входе, запуске и после каждого урока |
| `src/features/account/AccountGate.tsx` | не пускает без входа; ждёт первой синхронизации на новом устройстве     |
| экраны                                 | `/auth`, `/new-password`, `/leaderboard`, блок аккаунта в профиле       |

**Синхронизация.** Весь прогресс устройства — это снимок базы (тот же, что «Сохранить копию
прогресса»). При синхронизации снимок из аккаунта объединяется с данными устройства: уроки,
опыт, карточки, достижения с обоих складываются, а если одно и то же есть в обоих — побеждает
больший прогресс. Результат сохраняется и на устройстве, и в аккаунте. Настройки этого устройства
(тема, голос) важнее настроек из аккаунта.

**Рейтинг** — опыт с понедельника. Другие видят только имя, опыт за неделю и серию; почту не видит
никто. Друзья добавляют друг друга по коду из 8 символов.

**Платный доступ** — пока только поле `plan` в профиле (`free` / `premium`). Менять его может
только сервер, не приложение. Оплаты нет.

## Настройка (один раз)

### 1. Проект Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и создайте проект. Регион — **Central
   EU (Frankfurt)**: ближе всего к России. Пароль базы данных сохраните, он понадобится только вам.
2. **SQL Editor** → вставьте весь файл `supabase/migrations/20261019000000_accounts.sql` →
   **Run**.
3. **Project Settings → API**: скопируйте **Project URL** и **publishable (anon) key**. Это
   публичные значения, их можно передать мне и вписать в настройки сайта.

### 2. Вход по почте

**Authentication → URL Configuration:**

- **Site URL:** `https://jane-english.netlify.app`
- **Redirect URLs:** `https://jane-english.netlify.app/` и
  `https://jane-english.netlify.app/new-password`.

Для локальной проверки можно отдельно разрешить те же пути на используемом адресе localhost.
Для опубликованного сайта достаточно двух точных адресов выше.

**Authentication → Emails → SMTP Settings.** Встроенная почта Supabase предназначена для проб:
письма приходят только на адреса участников проекта, с ограничением числа отправок. Для
регистрации остальных пользователей подключите свою почту для
рассылки (SMTP): например, Яндекс 360, Mail.ru для бизнеса, Unisender или Resend. Без этого
регистрация пользователей вне команды не будет работать. Подробнее — в
[документации SMTP Supabase](https://supabase.com/docs/guides/auth/auth-smtp).

**Authentication → Emails → Templates:** переведите письма на русский (тексты могу подготовить).

#### Код и ссылка для входа без пароля

Код подготовлен, но этот способ скрыт до завершения настройки письма. В **Authentication →
Emails → Templates → Magic Link** нужно сохранить содержимое
`supabase/templates/magic-link.html`, тема письма — `Вход в Jane`.

Письмо содержит `{{ .Token }}` для ввода кода и ссылку
`{{ .SiteURL }}/auth?token_hash={{ .TokenHash }}`. На сайте ссылка открывает экран подтверждения:
только нажатие «Войти в Jane» вызывает `verifyOtp` и создаёт сессию. Просмотр письма/ссылки сам
по себе не расходует токен. Переход работает и на другом устройстве: обмен не зависит от
PKCE-верификатора в браузере, который запрашивал письмо.

Затем на Netlify задайте `EXPO_PUBLIC_EMAIL_PASSWORDLESS=true` и пересоберите сайт. После входа
одним способом второй из того же письма уже не работает. Код имеет длину, заданную в Supabase
(поле принимает от 6 до 10 цифр). Повторная отправка доступна через минуту; серверные лимиты
продолжают действовать.

Этот вход предназначен для **существующих аккаунтов** (`shouldCreateUser: false`). Новые
пользователи сначала проходят регистрацию с именем и согласием на обработку данных.
Текущий вход по паролю остаётся доступен.

Проверка после настройки: существующий аккаунт → запросить письмо → войти по коду → выйти →
запросить новое письмо → открыть ссылку в другом браузере → подтвердить вход. Проверить также
ошибочный/повторно использованный код, просроченную ссылку и повторную отправку.

### 3. Вход через Google и Яндекс ID

- **Google** — встроен в Supabase: **Authentication → Providers → Google**. Нужен OAuth-клиент в
  Google Cloud Console (тип «Web application»), в него вписывается адрес обратного вызова,
  который показывает Supabase.
- **Яндекс ID** — свой провайдер типа OAuth2 (**Authentication → Providers → Custom**, идентификатор
  `custom:yandex`). Приложение создаётся на [oauth.yandex.ru](https://oauth.yandex.ru), доступ
  «Яндекс ID: адрес почты» и «имя». Адреса: авторизация `https://oauth.yandex.ru/authorize`,
  токен `https://oauth.yandex.ru/token`, данные пользователя
  `https://login.yandex.ru/info?format=json`. Яндекс отдаёт почту в поле `default_email`, а не
  `email`; проверим при подключении, понимает ли это Supabase.
На бесплатном тарифе Supabase можно до трёх своих провайдеров.

Порядок настройки и незавершённые внешние шаги: [AUTH-PROVIDERS.md](AUTH-PROVIDERS.md).

### 4. Переменные окружения

На Netlify: **Project configuration → Environment variables** (локально — файл `.env.local`,
образец в `.env.example`):

```
EXPO_PUBLIC_SUPABASE_URL=https://ваш-проект.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=publishable-ключ
EXPO_PUBLIC_AUTH_PROVIDERS=
EXPO_PUBLIC_EMAIL_PASSWORDLESS=false
```

Для начала оставьте `EXPO_PUBLIC_AUTH_PROVIDERS` пустым: регистрация и вход будут по почте и
паролю. Позже перечислите только настроенные провайдеры (например, `google`) — кнопки остальных
не показываются. После изменения переменных сайт нужно пересобрать (**Deploys → Trigger deploy**).
Команда `web:build` очищает кэш Metro перед экспортом: при проверке смены переменных старое
значение провайдера иначе оставалось в сборке, несмотря на новое окружение.

## Закон

Почта и имя — персональные данные. Закон 152-ФЗ требует хранить персональные данные граждан
России на серверах в России, а Supabase хранит их в ЕС. Перед запуском для пользователей из России
стоит проконсультироваться с юристом или перенести аккаунты на российский сервер (например,
Yandex Cloud): код для этого меняется только в `src/core/account/` и `service.ts`. Также нужно
указать в политике конфиденциальности, кто оператор данных и как с ним связаться.
